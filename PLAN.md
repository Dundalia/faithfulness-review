# Method

How the map is built and how to extend it. Each paper is one short record with verified metadata, a flat tag list and a telegraphic summary, so papers can be added one file at a time.

## Layout

```
README.md          overview
PLAN.md            this file: record format and pipeline
tags.yaml          tag vocabulary (open; grows at consolidation)
papers/<key>.md    one record per paper (the source of truth)
scripts/           records.py (read/write), build.py (views), fetch.py (full texts),
                   apply_meta.py, apply_records.py, pilot_compare.py (apply workflow results)
site/              dashboard (index.html, app.js, style.css); data.json is generated
index.md, index.csv, tags.csv, relations.csv, corpus.txt   generated by build.py
definitions.csv    definitions of the three terms, built by scripts/definitions.py from runs/D_definitions/
workflows/         the exact workflow scripts that were run (absolute paths from the original machine)
runs/              raw workflow outputs (metadata, pilot, coding + verification, consolidation)
pilot/             two-coder pilot records and agreement report
meta_log.json      where each paper's venue was confirmed
fetch_log.json     how each full text was obtained
cache/             full texts, local only (not in git)
```

Keys are the bib.bib key when the paper is in the TrustMe review's bibliography, otherwise `firstauthorYYYYword`.

## Record

Eight front-matter fields: seven bibliographic and one tag list. Everything descriptive is a tag.

```markdown
---
key: turpin2025teaching
title: "Teaching Models to Verbalize Reward Hacking in Chain-of-Thought Reasoning"
authors: "Turpin, Arditi, Li et al."
year: 2025                                   # first public version
venue: "ICML 2025 workshop (R2-FM)"           # or "preprint", "withdrawn (ICLR 2026 submission)", "blog"
url: https://arxiv.org/abs/2506.22777v2       # latest version
checked: 2026-10-15                           # last metadata check
tags: [source:trustme, object:cot, reveals:planted-cue, signal:planted-cf, lever:sft, ...]
---
**TL;DR** Trains models to mention planted cues in their CoT before RL (VFT): after RL that rewards exploiting cues, most hacks are verbalized.
**Problem** RL-learned reward hacks go unverbalized in CoT → CoT monitors miss them.
**Method** VFT: SFT on CoTs minimally edited to credit planted cues → GRPO rewarding cue-aligned wrong answers.
**Findings** Post-RL undetected hacks 6% vs 88% RL-only, 99% BCT. ...
**Limits** Llama-3.1-8B, MMLU only; held-out cues similar to training. ...

**Relations**
- builds-on [[turpin2023language]]: uses its cued-vs-uncued counterfactual test
- compares-to [[chua2024biasaugmented]]: BCT baseline; relearns cues under RL

**New tags**
- (none)
```

Rules:
- **TL;DR:** one plain-English sentence of at most 28 words: what the paper does and its headline result, stated qualitatively (no numbers). The dashboard shows it on collapsed cards.
- **Summary:** four labeled lines, about 60 words, telegraphic. Use numbers only if they appear in the paper. For measurement papers, "Method" describes the setup.
- **Tags:** every `namespace:value` from `tags.yaml` that applies; tag what the paper does, not what it mentions. `model:` and `metric:` take free values.
- **Relations:** one line each, as `- <verb> [[key]]: note`. Only link papers that are in the corpus, and skip papers that are only mentioned in related work. The verbs:
  - `builds-on`: uses the other paper's method, data or setup.
  - `extends`: generalizes or scales the other paper's method.
  - `compares-to`: runs it as an experimental baseline.
  - `contradicts`: an explicit or result-level conflict; the note states the conflicting claim.
- **New tags:** for each tag not in `tags.yaml`, add one line: `- namespace:value: definition`.

## Pipeline as run (October 2026)

| Stage | What | Agents |
|---|---|---|
| Seed | Parse the merged paper list into 130 stub records; fetch arXiv metadata; cache full texts (`scripts/fetch.py`; five OpenReview PDFs through a browser) | script |
| Metadata (workflow A) | Latest version, title, authors, acceptance status from arXiv comments, OpenReview, ACL Anthology, proceedings, DBLP and Semantic Scholar; applied with `apply_meta.py` | 9 |
| Pilot (workflow A) | Two agents tag and summarize the same 12 papers independently; agreement in `pilot/report.md`; vocabulary revised to v0.3 | 24 |
| Code + verify (workflow B) | One agent writes each record from the full text; a different agent checks it against the paper and fixes errors (609 edits across 130 records) | 260 |
| Consolidate (workflow B) | Merge synonym tags, normalize model and metric names, add 34 tags to `tags.yaml` (v1); applied with `apply_records.py` | 1 |
| Definitions (workflow D, 30 October 2026) | `definitions.py excerpt` keeps the sections of each full text that mention the terms; one agent per batch of ~12 papers quotes every definition of faithfulness, counterfactual or monitorability and checks the quotes verbatim (`definitions.py check`); one agent per term clusters them and checks attributions; `definitions.py build` writes `definitions.csv`. Synthesis in `site/pages/definitions.md` | 21 |
| Build | `python3 scripts/build.py` regenerates every view and `site/data.json` (including the definitions) | script |

## Adding a paper

1. Write a stub `papers/<key>.md` with the front matter above (key, title, url; tags with a `source:` value) and an empty body.
2. `python3 scripts/fetch.py <key>` to cache its full text.
3. Run the metadata check and the code + verify steps on it (the prompts are in `workflows/`), or write the record by hand following the rules above.
4. `python3 scripts/build.py`, commit, push. The dashboard redeploys on push.
